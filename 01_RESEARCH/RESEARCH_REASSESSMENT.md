# RESEARCH_REASSESSMENT.md — Critical Audit & Revalidation of Prior OSINT Platform Research

## 1. Executive Mandate: Why Questioning Everything Was Necessary
In the initial greenfield cycle, the primary objective was to prove out an end-to-end working prototype quickly. However, when evaluated by an independent multi-disciplinary review panel—comprising a Principal OSINT Architect, Senior Cybersecurity Researcher, AI/ML Research Engineer, Data Science & Algorithm Researcher, Knowledge Graph Specialist, Intelligence Analysis Specialist, Senior Software Architect, and Performance & Systems Engineer—several architectural, algorithmic, and methodological choices from Phase 1 were found to be **suboptimal for scaling beyond small workspaces (500–1,000 entities) or defending analytical conclusions against circular reporting**.

This document ruthlessly audits every prior recommendation, explicitly separates what remains valid from what was flawed or incomplete, and establishes the technical foundation for the redesigned v2.0 Blueprint.

## 3. What Remains Valid from Previous Research
Not every decision from Phase 1 was flawed. Revalidation confirms the following core principles remain technically sound:
1. **Local-First Single-Node Deployment Philosophy:** Rejecting mandatory multi-container Docker stacks (Elasticsearch + RabbitMQ + Redis + PostgreSQL, which require 8–16 GB RAM idle in [OpenCTI](https://github.com/opencti-platform/opencti)) in favor of an embedded local database architecture is essential for Windows 11 usability.
2. **SQLite in WAL Mode (`PRAGMA journal_mode = WAL;`) as the Transactional Core:** SQLite 3.40+ with Write-Ahead Logging and FTS5 remains the gold standard for zero-configuration, ACID-compliant local storage, provided analytical/vector workloads are augmented with columnar ([DuckDB](https://duckdb.org/)) or SIMD vector ([sqlite-vec](https://github.com/asg017/sqlite-vec) / [USearch](https://github.com/unum-cloud/usearch)) extensions.
3. **Fernet Symmetric Encryption (`cryptography.fernet`) + OS Keyring for API Keys:** Encrypting third-party API keys at rest with a restricted local key rather than storing plaintext `.env` files remains best practice.
4. **Strict Separation of Verified Facts vs. Inferences:** Preventing AI assistants from blending raw registry facts with speculative link analysis is supported by recent CTI GraphRAG literature ([Operationalizing CTI with GraphRAG, arXiv:2608.13050](https://arxiv.org/abs/2608.13050)).

## 4. Critical Missing Capabilities Discovered During Reassessment
1. **Defanged Indicator & Multi-Encoding Parser:** Real-world OSINT analysts paste threat reports containing defanged indicators (`hxxps://evil[.]example[.]com`, `185.220.101[.]34`, `user[@]domain[.]org`, punycode `xn--...`). Our previous regex extractor missed defanged IOCs entirely.
2. **Super-Node (Hub) Explosion Mitigation in Graph Pivoting:** In OSINT graphs, public resolvers (`8.8.8.8`), major CDNs (`Cloudflare AS13335`), and major registrars (`GoDaddy`, `Namecheap`) act as "super-nodes" with thousands of edges. Treating `AS13335` as a high-value correlation link between two domains produces catastrophic false positives. We must introduce **Inverse Entity Frequency (IEF) Edge Weighting** to penalize generic shared infrastructure.
3. **High-Value Public Data Sources Previously Overlooked:**
   - **[CISA Known Exploited Vulnerabilities (KEV) Catalog](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)** and **[FIRST.org EPSS API](https://api.first.org/epss/)**: CVSS base scores alone are poor predictors of real-world exploitation; combining NVD CVSS + EPSS probability + CISA KEV status is essential for defensive cyber triage.
   - **[GLEIF Global LEI API](https://api.gleif.org/)**: Completely free, keyless, authoritative API for global corporate legal entities and Level-2 parent/subsidiary ownership trees.
   - **[OpenSanctions / yente](https://www.opensanctions.org/docs/api/)**: Standardized sanctions, PEP (Politically Exposed Persons), and watchlists using the [FollowTheMoney](https://github.com/alephdata/followthemoney) ontology.
   - **[Wikidata SPARQL API](https://storage.imrpress.com/IMR/2115645204216127500/application/2942-3309-53-6-50577.pdf)**: Structured cross-lingual organizational, domain, and person resolution.
   - **[URLScan.io Public API](https://www.xftf.org/lessons/intro-to-osint/osint-sources/domains-dns-infrastructure)** and **[AlienVault OTX DirectConnect](https://otx.alienvault.com/api)**: Passive DOM/HTTP transaction history and community threat pulses.
4. **Archival & Court-Defensible Evidence Packaging (Berkeley Protocol / WACZ / W3C PROV):** Storing only a JSON snippet and SHA-256 hash is insufficient when a web page changes or vanishes. Recording full HTTP response headers, retrieval timestamps, W3C PROV lineage (`wasDerivedFrom`, `wasAttributedTo`), and optional WARC/WACZ snapshots aligns the platform with international digital evidence standards ([The Modern OSINT Stack, 2026](https://medium.com/@adnanmasood/the-modern-osint-stack-from-search-tools-to-agentic-intelligence-systems-16d417f2b489)).
